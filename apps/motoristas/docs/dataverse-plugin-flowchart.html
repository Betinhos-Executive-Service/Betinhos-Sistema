Fluxograma do Plugin Dataverse

Este arquivo descreve o funcionamento do plugin Betinhos.DriverRecordSharing. Ele mostra como o plugin decide conceder acesso, manter acesso ou revogar acesso quando um motorista entra, sai ou é trocado em um registro.

Entidades diretas Serviço, troca de carro, posse de veículo, colisão e recibo.
Entidade especial cr40f_servicosporpassageiro tem fluxo próprio porque depende de serviço e passageiro.
Regra central Primeiro ele descobre o motorista atual. Depois tenta descobrir o antigo. Aí compara os dois.
Fallback atual Se a Pre Image falhar, o plugin tenta achar o motorista antigo pelos compartilhamentos já existentes.

Fluxo 1: Entidades Diretas

1. Evento chega

Plugin roda em Create ou Update de serviço, troca, posse, colisão ou recibo.

2. Verifica se a entidade é suportada

Se não for uma entidade do mapa interno, o plugin para sem fazer nada.

3. Lê o registro atual

Busca o valor atual do campo de motorista no Dataverse para saber quem está no registro agora.

4. Resolve o motorista atual

Vai em cr40f_funcionarios, pega o cr40f_emailmicrosoft e procura o systemuser ativo correspondente.

Se é Create

Não existe motorista antigo. Então o plugin só concede acesso ao motorista atual, se existir.

Se é Update

Ele tenta descobrir quem era o motorista antigo para saber se deve revogar acesso.

5. Descobre o motorista antigo

Primeira tentativa: usar a Pre Image. Segunda tentativa: olhar usuários que já estavam compartilhados no registro.

Sem motorista antigo

Exemplo: serviço estava vazio e agora ganhou motorista. Resultado: concede acesso. Não revoga nada.

Com motorista antigo

Exemplo: saiu Motorista A e entrou Motorista B. Resultado: concede para B e revoga de A.

6. Concede acesso ao motorista atual

Se o motorista atual foi resolvido com sucesso, o plugin compartilha o registro com esse usuário.

7. Se for serviço principal, compartilha a hierarquia

Em cr40f_reservadeveculos ele também compartilha a manutenção ligada, os links de passageiros e os passageiros.

8. Revoga acesso do motorista removido

Se encontrou motorista antigo diferente do atual, o plugin revoga o compartilhamento do antigo.

9. Se for serviço principal, revoga a hierarquia também

Revoga serviço, manutenção, links de passageiros e passageiros, mas só remove passageiro se nenhum outro serviço daquele motorista ainda precisar dele.

10. Finaliza

Trace grava quantos motoristas atuais e anteriores foram encontrados. A execução termina sem depender cegamente da Pre Image.

Fluxo 2: Serviço por Passageiro

1. Evento chega

Plugin roda em Create ou Update de cr40f_servicosporpassageiro.

2. Lê o vínculo atual

Busca qual é o serviço atual e qual é o passageiro atual ligados naquele item.

3. Resolve os motoristas atuais pelo serviço

Ele não lê motorista direto do link. Ele sobe até o serviço e resolve o motorista que está no serviço.

4. Descobre o estado anterior

Se tiver Pre Image, usa o serviço antigo e o passageiro antigo. Se não tiver, tenta usar os compartilhamentos atuais do próprio link.

5. Concede acesso ao link serviço-passageiro

Todo motorista atual recebe acesso de leitura ao item de cr40f_servicosporpassageiro.

6. Concede acesso ao passageiro

Se existe passageiro válido no link, o plugin também compartilha o passageiro com o motorista atual.

7. Revoga o link do motorista removido

Se um motorista antigo saiu, o plugin revoga o compartilhamento daquele item do serviço por passageiro.

Passageiro ainda continua sendo usado

Se o mesmo passageiro ainda estiver em outro link de serviço para o mesmo motorista, o acesso ao passageiro é mantido.

Passageiro não é mais usado

Se não existir mais outro vínculo válido, o acesso ao passageiro antigo é revogado.

8. Finaliza

O plugin encerra com concessão e revogação alinhadas ao estado final do serviço e do passageiro.

Regras Importantes

  • Se o funcionário não tiver cr40f_emailmicrosoft, o plugin não compartilha e não bloqueia.
  • Se existir email Microsoft mas não existir systemuser ativo correspondente, o grant falha.
  • Se existir mais de um systemuser ativo para o mesmo email, o grant falha.
  • No cenário de troca, o plugin trabalha em cima de “motoristas atuais” versus “motoristas anteriores”.
  • O fallback novo evita erro quando a Pre Image não chega, mas ainda tenta revogar corretamente.
